# オフラインデモの仕様

## 処理の流れ

```text
固定CSV + settings.json
  -> load_fixture: OHLCV/日時/順序を検証
  -> replay_bars: 初期状態から、その時点までの足を順に渡す
  -> process_bar: 指標 -> 見送り/エントリー/保有/決済
  -> enter_* / exit_* / mark_*: 仮想約定と資産評価
  -> build_scenario: 各時点の結果・約定・決済済み履歴
  -> GET /api/demo: 読み取り専用の固定JSON
  -> render / drawCharts: 価格・資産・判断・取引を表示
```

再生はブラウザ内の表示カーソルです。サーバー側の取引を再実行するボタンではありません。
再読み込み・再起動は常に同じ結果から始まり、複数タブでも結果を変えません。

## 再利用と追加範囲

判断・ポジションサイズ・新規約定・決済・評価資産の計算は、既存の `daytrade_runner.py` をそのまま使用します。
既存バックテストモジュールに小さい `replay_bars` インターフェースを追加し、`max_drawdown` を再利用します。
従来の `simulate_symbol` と運用ランナーの入口は変更していません。
`replay_bars` は `settings_override` と `skip_portfolio_risk` という既存の引数を利用します。
デモのために売買ルールや既存損益式を変更していません。

## 入力と分離

- データは `etf_mobile/interview_fixtures/{trend,reversal,range}.csv` の架空OHLCV。
- 2026-05-20 09:00〜09:40 JSTの41本。実在銘柄ではなく `DEMO-A/B/C` と表示する。
- 最初の30分は共通の小幅な価格変動。その後に上昇・下抜け後の反転・レンジが続く。
- 分岐を観察するために作った入力で、実相場のサンプリング・予測・収益評価ではない。
- ランダム生成や現在時刻による入力変更をせず、CSVと全設定をGit管理する。
- 1ケースあたり初期資金10万円、独立評価。3ケースを同時に取引するポートフォリオではない。
- `data/`、`data_daytrade/`、口座情報、RSS、ログ、既存履歴を読み書きしない。
- サーバーの結果はメモリ内のみ。ユーザー操作のJSONダウンロード以外、結果ファイルを保存しない。
- デモの設定は `daytrade_config.py` の運用設定を読まず、全キーを明示した固定ファイルから渡す。
- 外部銘柄を参照する市場フィルターは無効。ファイルに依存する口座全体のリスク判定も独立評価ではスキップ。
- サーバーは `127.0.0.1` にのみバインド。GET/HEADで既知の画面・JSONのみを返し、注文や更新のPOSTを提供しない。
- HTML/JS/CSSは同梱。CDN、外部フォント、画像配信サービス等に依存しない。

`load_fixture` は空データ、非有限値、正でない価格、矛盾したOHLC、負の出来高、不正日時、重複・逆順を拒否します。
足の欠損と複数日への対応は汎用ローダーの保証に含めず、固定の41本はテストで確認します。

## 固定条件

寄り付き30分の高値/安値を抜け、VWAP条件を満たすとエントリーします。
リスク予算は0.3%、投入比率は最大40%。初期ストップ幅に対し利確1.2R、手数料は片道0.05%、
スリッページ0.05%、スプレッド0.05%、呼値0.1です。
1日1取引、09:37新規締切、09:40手仕舞いという短縮した固定セッションにしています。
説明する分岐を絞るため部分利確・トレーリング・ギャップ/他銘柄市場/ARフィルターは無効です。
取引結果は設定ファイルに含めません。株価の結果欄もなく、すべてエンジンで導出します。

全キーは `settings.json` にあり、既存エンジンの設定項目が変わった場合は明示更新が必要です。
設定の暗黙の既定値変更でデモ結果が変わることを防ぎます。

## 約定と損益のモデル

確定足の終値を入力に新規仮想約定します。新規の足で決済しません。
買い新規と空売り決済は価格に不利なコストを足して切り上げ、売り決済と空売り新規は差し引いて切り下げます。

```text
買う価格 = ceil(元の価格 * (1 + slippage + spread/2) / tick) * tick
売る価格 = floor(元の価格 * (1 - slippage - spread/2) / tick) * tick

新規直前の資産倍率 = E
投入比率 = w、片道手数料率 = f
新規後の資産倍率 = E * (1 - w*f)
買いの価格収益率 r = 決済価格 / 新規価格 - 1
空売りの価格収益率 r = 1 - 決済価格 / 新規価格
決済後の資産倍率 = E * (1 - w*f) * (1 + w*r - w*f)
円損益 = 初期資金 * (決済後の資産倍率 - E)
```

これは既存エンジンの比率モデルです。数量を発注する現金・建玉台帳ではありません。
新規直後には新規手数料のみが資産に反映され、保有中は終値で時価評価、決済時に残りの価格コストと手数料が反映されます。
画面の評価資産はこの時点のモデル値であり、常に即時清算後の残高ではありません。
内部計算は既存の浮動小数点、表示時に小数2桁へ丸めます。テストは独立したDecimal計算と照合します。
`pnl_rate` は初期資金全体ではなく各取引直前の資産に対する比率です。円表示は資産倍率の差から求めます。

上昇ケースは09:30に1004.8で買い、09:33に1012.6で決済。反転ケースは995.2で空売りし、1003.2で買い戻します。
どちらも投入比率40%、両側手数料を含み、それぞれ+270.451452...円、-361.475099...円です。
同じ足でストップとターゲット双方に届く場合、既存実装はストップを優先します。
ストップを飛び越える始値にも対応しますが、板・足内経路・注文遅延を再現するものではありません。

## 再現性

同じデータ・条件から毎回状態を初期化します。`process_bar` が持つ表示用の実行日時だけをシミュレーション日時へそろえます。
表示用フレームには現在時刻、実行環境のパス、乱数を含めません。
全JSONをキー順固定で直列化し、指紋をSHA-256として付与します。指紋は自分自身の欄を除いたJSONに対して計算します。
検証時の指紋は [DEMO_VERIFICATION.md](DEMO_VERIFICATION.md) を参照してください。

## 残る制約

楽天や他の証券会社への実注文は未実装・未検証です。実注文を有効化する切り替えもありません。
単元株、端数、借株料・金利、税、空売り制限、注文の一部約定、通信障害後の注文照合はこのモデルに含みません。
固定ケースは機能検証用であり、実運用成績・収益性・本番の連続稼働を検証していません。
ローカルの標準HTTPサーバーは公開サービス向けではありません。インターネット公開は行わず、認証や運用監視の完成も主張しません。
