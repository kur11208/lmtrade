# LMTrade 技術面接用ガイド

## 準備と起動

必要なのはPython 3.10以上とChrome / Edge等のブラウザだけです。
ネットワークからのデータ取得、APIキー、楽天へのログインはありません。

```powershell
cd C:\work\lmtrade
python demo.py
```

クローン先が別の場合はそのフォルダーで実行します。Windowsでは `py -3 demo.py` でも起動できます。
ブラウザが開かなければ、ターミナルに表示されたURLを開きます。
8765番が使われていたら自動で次の空きポートへ進みます。明示する場合は `python demo.py --port 8888`。
終了はターミナルで `Ctrl+C`。再起動時にも同じ初期画面と結果が出ます。

面接前に `python demo.py --check` を1回実行しておきます。
Python未導入の環境では事前にインストールしてください。Python同梱の実行ファイル化は行っていません。

## 画面共有での操作

1. 起動直後の「上昇」を表示。初期資金10万円、+270.45円、取引履歴の買い→利確を確認する。
2. 「最初から再生」を押す。約13秒で41本の1分足を再生する。寄り付き30分は見送り、09:30に新規約定、09:33に決済する。
3. 必要なら再生を一時停止し、スライダーを31本目にする。新規約定の理由、投入比率40%、手数料による評価額の減少を見る。
4. 「下抜け後の反転」を押す。空売り後に価格が反転し、-361.48円を損切りしたことを見せる。
5. 「レンジ」を押す。条件に未到達で取引しない判断と、損益0円を見せる。

起動後の主操作は「再生」と2回のケース切り替えです。
「結果を保存」で全ケースの設定・各時点の判断・約定・損益をJSONとして保存できます。
すべて架空データであり、実口座や運用履歴の画面共有は不要です。

下の説明順序で該当関数へ移動する。すべてを逐行で読まず、1本の足が通る場所を追う。

「同じCSVと設定から同じJSONが生成されることを、別プロセス・別作業ディレクトリーでも確認しています。

## 想定質問と回答の要点

| 質問 | 回答の要点 |
| --- | --- |
| なぜ独自の売買ロジックをデモ用に書かなかったか | 運用・バックテストと判断がずれないよう、`process_bar` を共有した。今回追加したのは固定入力と表示への接続部分 |
| なぜ既存画面をそのまま使わないか | 既存画面にはリアルタイム状態・管理・外部データ連携がある。面接は読み取り専用の小さい入口にし、環境依存の操作を減らした |
| 入力データの問題にはどう対応するか | 非数値、無効なOHLCV、時系列の逆転・重複を検知して起動を失敗させる。欠損の補完で結果を都合よく作らない |
| バックテストの先読みはどう防ぐか | その時点までの価格リストを渡す。全期間を実行した前半と、前半だけを実行した結果が一致することを検証 |
| 本当に再現できるか | 日時・乱数・外部レスポンスを結果に混ぜない。全条件とCSVを固定し、同一JSONとSHA-256を検証 |
| 利益が出るデータにしただけでは | 分岐を観察するテスト用入力。損失・取引なしも提示し、収益性とは切り離す。実運用の有効性は未判定 |
| 手数料や約定価格はどう扱うか | 新規・決済双方の手数料と不利方向のスリッページ・半スプレッド、呼値丸めを既存関数で計算。独立式で照合 |
| なぜWebで再生しても結果が変わらないか | 起動時に計算が完了し、操作は表示位置を変えるだけ。複数タブも共有の取引状態を更新しない |
| ポートフォリオの制御は動くか | デモは各ケースを独立評価し、ファイルに依存する口座全体のリスク判定はスキップする。実口座全体の検証はこのデモの範囲外 |
| 実注文が入る可能性は | デモは読み取り専用HTTP。注文API、口座情報、注文キュー、運用ランナーを呼ばない。JSONもpaper固定 |
| なぜフレームワークを使わないか | 3ケースのローカルデモには標準ライブラリで足りる。依存導入や環境差を減らす判断。本番の公開Web用途にはこのサーバーを使わない |
| 非同期処理や競合はどう扱うか | 起動時に固定結果を計算し、その後は読み取りのみ。サーバー側の再生セッションやファイル更新競合を持ち込まない |
| テストは何を保証するか | 固定入力の機能と数値、非アクセス、HTTPと画面操作。実相場の収益、楽天接続、実約定は保証しない |
| AIをどこに利用したか | デモ入口、UI、リプレイ補助、テスト・文書の整備。既存コアは別コミットで保存。詳細は変更来歴を参照 |
| 最も難しかった点は | 実際に説明できる範囲で、環境依存と売買処理の分離、先読み防止、数値検証などを挙げる。経験していない判断を自分の経験にしない |

## 制約と今後

固定の架空1分足・単一銘柄単位の再生です。実口座、外部フィード、板・約定遅延、注文数量の整数化、借株料や信用取引の制限は含みません。
実数の投入比率による仮想評価なので、10万円で当該株数を本当に発注できるという意味ではありません。
本番化には、連続したデータ品質の検証、数量・注文状態・約定照合、監視と障害復旧、実注文連携を別途設計します。
既存の自動起動凍結は維持します。
